Use Case Write Up 

Companies should invest in developing use cases because they help establish clear expectations for how a system should function before development begins. Clearly defining requirements, constraints, and expected outcomes can reduce ambiguity and help make software more reliable and predictable (Nguyen, 2026). A use case supports this by outlining what a user is trying to accomplish and how the system should respond throughout that process. 

 For Scenario #2 in this week’s assignment, identifying the overall goal was rather clear, as the need to maintain appropriate workforce levels and skill coverage was defined early on. Determining the individual interactions between the shift supervisor and the system was more difficult. I had to consider which decisions should be made by the supervisor and which tasks should be handled by the software, such as checking officer availability, identifying scheduling conflicts, and determining whether the required skills are represented on a shift. 

 I believe breaking the process into individual interactions made it easier to distinguish between user actions and system responses. It also helped identify situations outside the main process, such as when no qualified officer is available to fill a staffing gap. Overall, this approach helped turn a broad scenario into a specific process for how the software should function.
